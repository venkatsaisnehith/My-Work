# Roadmap

## First: make the profile accurate

- Confirm the public name, headline, biography, and contact links.
- Add verified metadata and links for both publications.
- Publish a reviewed CV.
- Choose a focused AI engineering and research theme informed by the existing work.
- Select hosting and configure the production `SITE_URL`.

## Build a sustainable body of work

Start with one substantial project. Define a question, a baseline, an evaluation method, and an achievable outcome before adding features. Keep its source reproducible and write down what failed as well as what worked.

A useful first sequence is a research reproduction, an applied AI system, and an evaluated deployment. Treat this as a direction, not a claim that these projects have been completed. Pick the actual topics around the owner's research interests and the requirements of target roles.

Use a manageable cadence:

- Add a short learning note when there is a concrete lesson to preserve.
- Review progress weekly and identify the next experiment.
- Publish a considered technical article approximately every two weeks when the work supports it.
- Write a monthly reflection connecting experiments, project decisions, and remaining questions.

The goal is a useful record that remains understandable months later. Content quality and evidence matter more than an uninterrupted streak.

## Apply alongside the work

Maintain a separate private application tracker. For each opportunity, record research fit, degree requirements, funding or contract duration, nationality restrictions, sponsorship confirmation, and the relevant portfolio evidence. Tailor outreach to a specific team's work and link the most relevant article or project.

Keep personal application records and immigration documents out of this public repository. A lab's public funding or previous sponsorship does not establish eligibility for every vacancy.

## Later improvements, when needed

- Expand architecture diagrams using the supported image blocks, always with an accessible text explanation.
- Improve topic discovery as the writing collection grows.
- Add a real project demo when it can be maintained and evaluated.
- Consider a managed contact service only if GitHub and email links are insufficient.
- Consider an editing interface only if file-based publishing becomes a genuine obstacle.

Any service that stores messages or requires authentication needs a deliberate implementation and hosting decision. The current site stays portable: one source repository, one static build, and no required database.
